ORA Appendix

Evaluation details, failure audit and provenance for ORA: Open Robot-Use Agents.

Protocol

RoboTwinCohort rpent-zeroshot-v4-g004, source 654d265b; all 250 cases of the published C2R list, run directly on the randomized scenes with no clean-scene pass.
LIBERO-ProRefreshed cohort rpent-zeroshot-overhead-g005, run source a5ed51d8; 800 Task and Swap cases on the current LIBERO default.
LIBEROThe same g005 cohort reruns all 400 cases using official base-suite instructions. The previous table combined g003 with g004's 60 instruction-corrected cases (48/60 to 56/60 on those cases).
Model and budgetSelf-hosted DeepSeek-V4.1-Flash, low reasoning effort, task memory off. One scored outcome per case; at most 80 robot decisions, 200 model calls, 10,000 simulator steps and six hours. Five g005 cases had an infrastructure failure without a verdict and were rerun once as explicit -r1 replacements. The original attempts remain in the evidence; scores use their replacements.
TermsTask: a benchmark task. Case: a task with one seed from the published list. Episode: one attempt at a case. Round: one attempt within a session of several rounds on the same scene. Decision: one call that moves the robot.
Success checkThe model may call check_task, which returns the official success result for the current state without ending the episode. It never sees the check's code. We have not confirmed whether RPent's agents have an equivalent query.
SuccessThe environment's own verdict, from a sealed, valid evaluation. A case without a valid outcome counts as a failure in the charts; the exact tables also give the rate over valid outcomes.
Versus RPentSame cases, different conditions: RGB-D images, geometry and grasp tools, ORA's task text (RPent's seed-specific wording for nine place_a2b cases), different action and time budgets. RPent's C2R protocol explores the clean scenes first and carries task memory to the randomized ones, with LingBot-VLA as its primitive.
Harness versionRoboTwin retains g004. LIBERO and LIBERO-Pro use g005 after the overhead-footprint change (integration 0084), with official base-suite instructions and restored observation rules. Several changes separate g005 from the old tables, so the rerun is not an ablation of overhead localization.
Leaderboard notesRPent lists GR00T-N1.7, π0.5 and StarVLA without stating how they were run. RPent / GPT-5.5's 62.4% is the repository's update; the paper's Codex row reports 58.0%.

What changed in the full rerun

On the 399 cases with valid outcomes in both LIBERO tables, the refreshed run rescued 36 failures and lost 34 previous successes (exact McNemar p = 0.91). On 796 LIBERO-Pro pairs, it rescued 67 and lost 52 (p = 0.20). The small overall increases do not establish a reliable gain. This rerun includes several harness changes and cannot isolate the effect of overhead localization. It replaces the earlier, incomplete progress readout.

Geometry calculations in model responsesA corpus audit labelled 12.2% of 35,270 responses as manual geometry derivations. A separate prompt-only test on 11 completed pairs of previously failed RoboTwin cases found arithmetic in 76.2% of baseline reasoning calls and 76.3% with calculator-routing instructions (912f4f10). These are different populations and measures. Three g012 runs wrote an upward quaternion for “approach from above”; world-axes poses added in 7cc9e9eb.corpus count, run audit

Two controlled tests did not establish an improvement: RoboDojo motion-safety fixes, 12 rounds with the fixes against 11 without, of 102 each (same commit b08e706f). A closed grasp skill on LIBERO: 35 with the skill against 41 without, of 60 paired states (p = 0.18). Single LIBERO reruns are noisy: 15 of 30 control failures succeeded on a plain rerun.

Still open

Long tasks: 52–64% on LIBERO-Long and the two LIBERO-Pro long suites, against 91–98% on Spatial and Object. RoboDojo: a first scan of 42 two-arm tasks[2] on October 6, on an earlier harness, solved 18 of 126 rounds and 9 tasks at least once. In 64 of the 108 failed rounds the target was reasonable and the motion went wrong (27 of these judgements are low-confidence). The benchmark tables compare complete systems in simulation using one ORA language model. The component tests above evaluate individual changes under narrower conditions.
