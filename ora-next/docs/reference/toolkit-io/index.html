Toolkit I/O evidence v1

本页定义可选的数据接口记录。默认关闭；旧 run 缺少本目录不影响原评估。实现入口见 interface README。

布局

native/toolkit-io/calls.jsonl 是 ora.toolkit.io-event.v1 单 writer 事件流； native/toolkit-io/blobs/sha256/<digest> 保存原字节和公开 semantic envelope。 replay 写独立输出根；同一布局的 comparisons.jsonl 每行 ora.toolkit.comparison.v1，包含 reference（comparison blob）、source_invocation_id 和 evaluation_invocation_id。源 run 不修改。

每次 begin/end 包括 sequence（全文件从 0 起）、invocation_id、identity、attempt、 semantic_request_hash、request、state_before。end 加 status=ok/error/timeout、 response_ref、source、cache_hit、error、state_after。state_after 未独立采样即 null。 未配对 begin 是 incomplete，不当成成功；重复/跳号/重叠/缺 begin 拒绝。 工具可以给调用加 note（interface/call_note.py），begin 和 end 都带，只作证据： 不进 request，也不进 semantic_request_hash，所以 replay 的匹配不变，环境也看不到它。 目前 note.route 记每次关节轨迹移动的路线（planner.PathPlan.route；recover_pose、 return_home 记 recovery），没有 note 的调用事件字节不变。 重试同一 invocation，attempt 从 0 起，只对显式配置的外部服务自动重试；动作永不重试。

request = {identity: <语义身份>, inputs: <带路径的实际引用>}。 身份包含 schema=ora.toolkit.request.v1、method、method_version=1、parameters（展开 默认值）、inputs（不含 path）、observation（id/hash）、binding、capabilities。 semantic_request_hash 只 hash request.identity。

canonical JSON 为 UTF-8、ensure_ascii=False、sort_keys=True、separators=(",", ":")、 allow_nan=False、无末尾换行。只接受严格有限 JSON；数组顺序保留，int/float/bool 不混同，未知方法参数由显式 Python 签名拒绝。输入身份保留 sha256/bytes/media_type/ array/json_pointer/byte_scope；不包含路径或端点地址。

invocation_id 是 identity 的同一 canonical SHA-256。identity 包含 run_id、round_index、 tool_call_id、interface_ordinal、boundary 和 before/after 逻辑 token。token 为 {tool_call_id, interface_ordinal, phase}；不是物理时间。重试不换 identity。

source：segment/segment_points/ground/grasp_candidates 为 external_service； submit_action/report_issue/finish_episode 为 agent_control；其他为 simulator。

公开响应

response_ref 为 BlobRef，指向 ora.toolkit.response.v1 JSON 原字节：method、status、 data、provenance、error。provenance 有 source、projection（method.v1）、observation、 binding、sources。公开字段投影定义在 projections/services；从不 dump 原 worker 或控制 对象。响应 envelope 的错误只保存公开 code/retryable，不保存异常文本、URL、凭据或堆栈。 记录器自己的故障另存 gaps.jsonl（见下文），不属于模型可见响应。

BlobRef：path、sha256、小写 hex、bytes、media_type；裸数组额外 array={dtype,shape,order,byteorder}，禁止 object/structured dtype。NPY 容器与裸数组 编码区分。每次读校验长度和 hash，symlink/parent traversal/根外路径拒绝。

公开路径只允许：toolkit 的 digest blob；policy-observations/<id>/observation.json、 proprioception.json、<camera>/rgb.png、depth-m.npy、calibration.json。路径类别合格之外 还必须由可信装配层依据该边界发布引用注册；不得枚举未来文件。其他 receipt/probe/ policy-state/manifest 由可信装配器投影进 toolkit blob，不整目录开放。

Replay 与 snapshot.v0

simulator/控制严格按父调用的 ordinal 消费。缺请求报 NotRecorded；动作/控制偏离报 Divergence；第二次动作提案拒绝；绝不在线补调用 worker。submit 返回历史提交确认， 不把后续回执或观测变成调用前可见。官方 check 没记录不使用 final verdict 补齐。

外部服务每次重算。精确匹配当前历史请求后比较并消费；新服务请求可以计算，comparison unavailable 且不推进游标。内容比对与完整 envelope 审计分开，见下节；原 tool-result、 manifest 或不同投影不是可比裸响应。comparison 与 payload 分开，simulator 的 payload 逐字节不变。

接受 rsi.traj.snapshot.v0，available_at_boundary 与 replay_evidence 分开。 可选 toolkit_io 为 ora.toolkit.snapshot-index.v1：calls 文件引用、snapshot_root（固定 日志副本所在根）、selected_tool_call_id、selected_round_index、next_interface_ordinal=0、 exact_interface_replay=true。原产物按 source run 解析，calls 按 snapshot_root 解析。 日志必须已固定字节、校验 hash；不读取追加中的最新日志替代快照。

before_call 为 K 从 0 起；after_native_action 为 N 从 1 起，但 v1 没有中途接口 cursor， next_interface_ordinal=null/exact=false，导入接口 replay 报未记录。仅显示 simulator/ controller 数据不等于能够从该物理边界继续原调用。

旧 snapshot 恢复观测与本体感知的原文件；明确标 provenance.reconstruction=legacy_artifact、 exact_interface_bytes=false，不声称存在从未记录的接口 envelope。receipt/check 要有明确 调用/完成绑定。缺 request 的 probe/align/reach 不按相似参数猜。旧服务响应 scope 不同则 只重算、comparison unavailable。没有读取 GT 的能力；check_task 必须显式开启。

外部服务的内容比对

四个方法 segment、segment_points、ground、grasp_candidates 各自声明相同的 volatile JSON pointer：/data/metadata/request_id、/data/metadata/latency_ms、 /data/metadata/timings、/data/metadata/queue。只删这些明确路径，绝不递归删同名 字段。后两项为公开投影预留；当前客户端投影未发布的原始字段不会为了比较而导出。 服务/model/configuration identity、随机 seed、候选计数和排序都是内容，不属于 volatile。

comparison 的 status 为 equal / within_tolerance / different / unavailable；前三者 scope 为 semantic_content。equal 表示除 volatile 和存储路径外，字段及数组值相同； within_tolerance 表示全部差异都在下面的绝对容差内；任何离散变化或超容差即 different。 每次比较仍保留 reference_sha256 / actual_sha256（完整 envelope）、envelope_equal、 reference_content_sha256 / actual_content_sha256（去 volatile 和 BlobRef.path 后的 JSON， 数组保留原 blob hash，因此容差内变化仍有不同 content hash）、volatile_fields。 没有绑定完整服务身份或当前游标没有可比请求则 unavailable。

字段 默认绝对容差（rtol=0） 摘要
backend_score、model_score、scores 1e-6 最大绝对差
poses_camera 的平移（m）、contact_points_camera（m）、openings_m（m） 1e-5 最大绝对差
poses_camera 的旋转矩阵元素（无量纲） 1e-5 最大绝对差；不是角度容差
mask 0 不同像素 different_pixels、pixel_iou（空并集为 1）
dtype、shape、存储顺序、计数、rank/source_index/query_index、其余字段 精确 字段变化/缺失/数量变化

differences 是逐 JSON pointer 的差异摘要，含 kind、within_tolerance；数值另有 max_absolute_difference、absolute_tolerance、relative_tolerance。大数组从两个 store 校验 hash/长度后读取，绝不把 BlobRef 的路径差异当数值误差。 candidates 单独报告数量及排序：SAM3 比较按位的 query_index/source_index/rank； CGN 报告 pose 行的精确置换，无法证明身份对应时 ordering_changed=null。不会重排候选使结果看起来相同；数值噪声伴随置换时， 仍按位置比较，可能无法证明候选身份的对应关系。

开启现有工具的只记录模式

在 RunSpec 顶层（与 runtime / policy 平级）添加：

record_toolkit_io: true

缺省或 false 不安装任何包装；RunPlan 仅在 true 时保留此键。它属于 orchestration， 不放进 runtime 环境配置，不传给 worker。仅支持 ManipulationToolRuntime 的 native_atomic_causal surface；其他 runtime 开启会在解析时拒绝。程序装配入口为 build_tool_runtime(..., record_toolkit_io=True)。

工具 factory 在旧客户端和工具初始化完成后安装 toolkit/host/recording.py。 原 invoke dispatch、工具算法、worker callback、动作准入和动作持久化各执行原来的那一次； 返回原 Python 对象，原调用异常原样重抛。不开重试、不补 service 请求、不执行在线 replay。 记录覆盖当前/已发布历史观测选择（含 proprioception 文件引用）、SAM3 三个方法、CGN propose 的原池、probe/align/reach 回调、submit_action 提交确认、check_task、issue/finish。 CGN 编译/排序结果仍原样给旧工具，接口只投影完整 backend pool。 提交确认不等于执行回执；稍后 worker 执行结果没有在调用前发生，不能在这里补写。

父身份取同 run 的 agent-events.jsonl 真实 tool_call_proposed：call 是全部提案的 0-based 索引，seq/model_call_id/tool_call_id 原样绑定。无上下文的聚合只读批次按提案顺序取首个 未完成的同名调用；显式上下文按 tool_call_id 精确选取。没有可绑定提案即拒绝记录， 不制造父 ID。状态只取此前最后发布观测；state_after 仍 null，不伪造额外采样。 每个外部请求保存实际 RGB/depth/pointcloud 的内容寻址数组引用；历史观测文件复制到 CAS， 当前观测文件仍引用 policy-observations。嵌套 _current 读取属于包住它的公共操作， 不产生重叠 begin/end。旧工具仍保持一次 submit_action 的派发语义。数据接口不再维护独立的次数守卫； 同步 toolkit（v5；分层的 v2 已于 2026-11-01 退役）通过 execute_action 逐次执行，由 Supervisor 的父调用预算与执行账本控制。

此开关是同进程证据仪表，不是工具隔离。记录器 fail-open：上下文、begin、输入 blob、 投影、输出 blob、end 或装配/恢复失败，都不能改变原调用的返回对象或原异常，不能阻止 或重复原调用。特别是 submitted-action.json 已落盘后投影失败，原 action_submitted 仍正常返回。原工具的准入、一次动作语义和拒绝保持原样；capture 不另行执行动作准入。 主动 DataInterface 调用仍严格校验，只有包住旧调用的 capture 使用 fail-open。 记录增加磁盘写入/校验成本，真实 wall-clock/预算可能受影响， 固定输入和时钟的工具结果与动作文件保持一致，不承诺带真实时钟的整个 episode 字节相同。 测试使用假服务与合成观测；真实 general_pickup smoke 由运行会话另行执行。

记录缺口：gaps.jsonl

native/toolkit-io/gaps.jsonl 是尽力追加的 UTF-8 JSONL。v1 每行是以下扁平对象， 不使用嵌套 error 或 identity：

{"schema":"ora.toolkit.gap.v1","run_id":"run-123","tool_call_id":"call-0","method":"submit_action","interface_ordinal":2,"stage":"project","error_type":"ValueError","message":"projection failed","unix_s":1792713600.0}
  • run_id 为源 run 目录名；tool_call_id 已知时保留真实父 ID，否则 null，不能借用并发调用的 ID。
  • method 是接口方法；context/装配阶段尚无接口方法时使用父工具名，初始化失败为 null。
  • interface_ordinal 在 capture 内已知时填写，从 0 起；上下文、准备输入等阶段为 null。
  • stage 只取 context / begin / project / end / store。store 包含输入/输出 blob I/O； project 内的 OSError 也归 store；hash drift 等完整性投影错误归 project。
  • error_type 是记录器异常类名，message 是其文本，最多 4096 字符；unix_s 是记录诊断的 Unix 秒，不是 simulator 时刻。该诊断不进入 tool result 或模型消息，也没有堆栈。

记录故障停止当前父调用的记录，原操作照常执行。context 或输入 store 故障发生在 begin 之前时，不污染 journal；下一个父调用重新尝试记录。已成功写入 begin 后的 project/response store 故障，会尽力追加 status=error、error.code=recording_gap 的 end 和同码响应 envelope，明确表示记录失败，绝不冒充原操作失败或成功。该 envelope 仅用于日志闭合，不返回给工具/模型；gaps.jsonl 仍以原 stage/error 标记该父调用， replay 必须拒绝它。成功闭合后，后续父调用正常记录、可独立 replay。

若 begin/end append 结果不确定（短写、flush/fsync 失败等），或 recording_gap 的闭合 也失败，冻结当前 writer，保留原字节，不截断、不重试 append、不补造回执。旧工具 与新工具此后都继续放行调用并写 begin gap，不为某个工具重开 writer 来绕过冻结。 同一个 run runtime 的 Recorder 和迁移工具 Dispatch 共用唯一 Journal，包含相同的 sequence、已写字节数和关闭状态；按既有 RPC 顺序执行父调用。新旧工具交替调用不会 被误判为外部写入。真正的外部追加仍拒绝记录，不刷新游标来掩盖损坏；这不增加多进程 或并发写入支持。这种磁盘/日志损坏不能保证恢复。 初始化失败则保留未包装的 runtime，只有一条父 ID 为 null 的 gap。 并发/递归调用只旁路自己的记录并写 context gap，不阻塞、不拒绝原调用，不借用当前 父身份；外层调用仍可记录。它不赋予原工具额外的并发安全保证。 工具内部自己新建线程时，ContextVar 默认 False，线程内调用既不记录也不留 gap。 当前 tool runtime 没有这种线程；这是已知边界，不据此声称线程内覆盖完整。

lib v0 另经 DataInterface.read_blob(ref) / save_array(value) 读取已授予的公开字节或 保存派生数值数组。它们没有新 simulator/service 调用，不分配 interface_ordinal， 不改变现有 15 方法的请求键与 calls schema。没有 register/path discovery 能力； read_blob 每次校验授权、长度与 hash。replay 的 save_array 只写 evaluation CAS， 输入的 dtype/shape/order/hash 随后绑定进服务请求。源 run 不修改。

gap 使用单次 append 写入；格式化、创建目录、open/write/close 失败全部吞掉。 磁盘满、短写或进程退出可能使 gap 缺失/不完整，因此没有 gap 不证明记录完整。 覆盖率需要与 agent-events 中父调用对照；有记录与 gap 并存时优先标 gap。 Replay 打开源 run 时，所选父调用存在 gap、存在无父 ID gap，或 gap 文件损坏/不可读， 均报 NotRecorded（未记录）；其他已知父调用的 gap 不影响当前调用。不会用残缺记录 声称完整接口 replay。只读轨迹展示和覆盖率不执行任何接口。

增量索引与离线开销

toolkit/host/event_index.py 记住文件身份和字节偏移，只解析新增完整行； 缓存提案身份、完成 ID 和发布事件，不保留无关大 payload。尾行未结束则留待下一次， 截断/替换或身份歧义走 context gap。发布观测仍按父提案之前的 seq 选取。 journal 的已写字节数也递增维护，避免每次 append 重编码全部历史。

阶段事件：stage()

工具可以用 stage(name, **fields)（ora/agent/toolkit/interface/stages.py）记下结果里没有的决定：试过又丢掉的候选、从默认值解出的值、被上限截掉的池。 没有调用方收集时它是空操作（工具调用模式从不收集），所以不改任何工具的结果、账本事件、本页的 begin/end 记录或耗时；字段是纯 JSON 值，一次调用最多 64 个事件， 事件不进工具的结果。code mode（policy.code_mode.library: extended）在每次脚本调用外收集它们，和结果、拒绝以及回执一起交给 ora/agent/toolkit/explain.py，按工具的 tools/<name>/explain.json 渲染成 robot.explain(r)（见 公共接口 的 code mode 一节）。 事件随该次脚本调用的记录写进 agent trace（嵌套调用 tool_result 的 payload.explain_inputs，ora.code-mode-explain-inputs.v1，见 ora/agent/code_mode/record.py），所以 explain 在会话重启后也能从记录渲染，不写进上面的 calls.jsonl。

现有的事件：vision_ground：query_cache{hit}；vision_segment：mask_omitted{query_index, reason, backend_score}； geometry_query：depth_window{window_px}；grasp_plan：display_cap{compiled, shown}、cut_candidate{candidate_id, backend_rank, reachable}、ik_unavailable{failure}。 模板声明的事件必须和工具源码里的调用一致（测试用 AST 核对）。

RUN 是源 run 目录。--at K 为从 0 起的第 K 次父工具提案之前，也可用唯一 tool_call_id；数字恰好同时匹配另一个 ID 时拒绝歧义。--list 返回 ora.toolkit.call-list.v1：calls[] 含 call / tool_call_id / tool / has_toolkit_io / has_gap；无父 ID 和未知父 ID 的 gap 数分别为 unbound_gaps / unknown_parent_gaps。 记录与 gap 可同时为 true，执行时 gap 优先拒绝；无父 ID 的 gap 保守拒绝所有调用。 没有 gap 不能推断全覆盖。--list 不创建输出、不请求服务。

脚本须定义 run(api, args)，返回严格 JSON 值（禁止 NaN、numpy 对象等）；api 是 所选边界的 Replay 或 LegacyReplay，能使用只读 lib。args 默认是父工具的原始 arguments；--args 显式替换脚本输入，但不会改 CallContext、历史请求或游标。 --tool NAME 支持 vision_ground、grasp_plan、grasp_execute、move_pose、move_to、 compute、check_task、finish_episode、observe；也可选该 run 冻结工具面中的其他已迁移工具。 换工具必须传 --args JSON。同工具的不同动作/准备文件仍会报 Divergence；换工具只提议动作。示例源码见 ground_geometry.py 及 examples README。

有 toolkit-io 的调用使用记录中的 run/round/parent/boundary/state/check_task 能力， 核对 agent-events 的父提案，再从 interface ordinal 0 开始逐项消费。只读地把 calls.jsonl 的固定字节复制到输出 source-calls.jsonl，后续源日志追加不改变本次游标。 不会搜索“某处同参的第一条”、跨过未消费的调用，或把后续仿真结果贴到新动作之后。 仿真响应保持记录的 envelope 字节；新仿真查询报 NotRecorded；不同动作报 Divergence；重复提交仍拒绝；有 gap、未完成接口调用或证据漂移均拒绝。 录下的 CallContext 原样保留。M7 在 replay 装配层单独开放 check_task 并标记能力覆盖， 仍须有该边界的判定记录，不倒灌最终判定；见下面的 M7 规则。

没有选中调用的 toolkit-io 时，使用 interface/legacy.py。RUN 若只有显式 snapshot.json（snapshot.v0，before_call），就按其唯一边界读取；普通旧 run 则只 选取提案之前最近的 fresh_observation_published，注册 manifest 声明的公开文件。 不从调用后的新观测、最终判定、未绑定控制日志猜测数据。能恢复的观测/本体感知保留 原始文件字节；缺失文件、探测和未绑定回执报“未记录”。旧工具输出与裸服务 envelope 范围不同，不能声明 equal；legacy 感知重算后写 unavailable comparison，reason 为 legacy_response_scope_not_equivalent。已提供的 snapshot 显式绑定旧回执时，仍沿用 legacy importer 的严格路径、哈希和动作 ID 核对。

感知必须显式传 --service-report，格式与 ora spec robodojo compose --service-report 相同：内容寻址文件名、ora.perception-readiness.v1、24 小时时效、协议版本、通过项及 ORA_SAM_PORT / ORA_GRASP_PORT（兼容既有服务环境变量）的端点匹配规则均沿用。 CLI 不启动服务、不分配资源、不读取 provider key。客户端在实际请求时核对 live identity。SAM3 使用现有默认客户端；CGN 使用默认 RoboDojo grasp_plan 配置 （hover_offset_m=0.04、32 raw candidates、1 forward pass），接口仅公开完整 canonical 候选池。非默认旧配置、不同 report/service identity、不同输入编码/参数或不匹配游标 会给 unavailable，不能伪装成同一服务。不给 report 时观察/纯计算仍能运行，首次请求 感知明确抛 ServiceUnavailable: service unavailable。每个重算请求的响应和 comparison 均落盘，比较口径仍是上文的 content 容差与完整 envelope 审计 SHA。

check_task 在 replay 总是获得研究侧调用权限，即使原局策略禁用了能力或没有该工具。 capability_override={check_task:true, original_policy_available:false, reason:"原局策略不可用"} 明确标记这项权限覆盖；否则 check_task=false、reason=null。这是 replay 授权信息，不 表示工具已调用它。原 context/check_task 及源日志不改，默认运行时权限不变。仍只能返回 该调用前边界实际记录的官方判定；没有就 NotRecorded，绝不读 final/control 判定补值。

result.json.mode 现在是执行模式 recorded（live 待 M7.4）；旧的记录来源分类移到 evidence_mode=recorded|legacy|null。源 calls、snapshot 和接口日志 schema 没有改变。 输出新增 progress.jsonl，每行均即时 flush，形状严格为 {t:<Unix秒>,stage:<名称>,done:<整数或null>,total:<整数或null>,message:<文字>}。 阶段依次 resolve、boot_worker、replay_controls、verify_state、run_tool、compare、done。 recorded 的三个仿真阶段明确 skipped，done=total=0，耗时为 0；未走到的失败阶段不伪造 事件。timing 含全部七阶段的单调时钟秒数。外部请求及接口内容比较在 run_tool 内同步 进行，该耗时计入 run_tool；compare 计结果收集和下面的模型投影。done 是即时终态事件。 解析失败也写 result/progress（源路径或输出目录本身无效时尚不能写）。

--tool 成功时新增 model_visible，直接复用实时 Pi 的 _project、causal projection 及 apply_hints；不修改模型投影函数，不用 replay 自己的单位转换规则。依赖源 run 的 冻结 surface 和 policy.context_composition，缺少时 status=unavailable，不猜默认值。 status=ok 时字段为 text（精确 UTF-8 文本）、sha256、bytes、artifact_ref（输出内原字节 .txt 文件）、stored_projection（输出内 canonical JSON 引用）、images 和 image_text。 输出图片也只写 replay 的 native/agent-artifacts/，原 run 完全只读。

同工具还返回 model_visible.comparison。原工具结果引用从该父调用唯一的 tool_result 事件取，校验 path、hash、bytes：

  • artifact.byte_equal/content_equal：本次 stored_projection 与原存档字节/去易变字段 后的内容比；原存档在 native causal 模式比模型文本丰富。
  • visible.byte_equal/content_equal：本次文本与从原存档经过 causal 投影得到的文本比； 后者不是 provider transcript，不承诺重建历史压缩或重复错误的会话状态。
  • original_artifact、original_visible_sha256、original_visible_scope 保留比较来源。

字节 SHA 不剔除任何字段。内容比较按实际感知结果结构，只删显式 JSON 路径： vision_ground 的 /diagnostics/{request_id,latency_ms,timings,queue}； grasp_plan 的 /diagnostics/{request_id,latency_ms,timings,queue} 及 /diagnostics/learned/{request_id,latency_ms,timings,queue}。花括号表示四条路径， 实际展开清单也放在每项比较的 volatile_paths 中。不递归删同名字段， 不改 compute 用户输出，不设数值容差（感知接口容差仍由前文 comparison 负责）。 缺历史结果时 comparison.status=unavailable，不声称相同。脚本结果不假定属于某工具， 不自动做模型投影。当前仍是同进程可信脚本；live 复原与动作执行见下节。

M7.4：live 诊断复原

调用方先分配 lane，再在相应执行主机使用：

ora toolkit replay RUN --at 8 --tool check_task --args '{}' --live --resource-profile PROFILE --json
ora toolkit replay RUN --at 4 --tool grasp_execute --live --resource-profile PROFILE --execute-action --json

--service-report 仍单独指定感知服务；不提供就没有感知能力。--live 必须显式给 --resource-profile；--execute-action 只适用于 live。ORA 不代替调用方申请 router 资源，但诊断进程仍按现有 ORA 协议 claim/release 所选 slot 的 lease 和 scratch。 退出、异常、超时和 SIGTERM 都经过 worker 关闭与释放路径。源 run 始终只读；默认 输出仍在 workspace/toolkit-replay/run_id/UTC-random，不能放入源 run。

  4. M7.4b 的放行门槛只看物理核对，保持零容差。重新渲染的传感器只用于统计， 不作为工具授权条件；sensor-verification.json（ora.toolkit.live-sensors.v2） 同时嵌入 result.sensor_report。工具始终使用源 run 当时发布的原字节，保留原 manifest/mask/candidate 身份；新捕获原件单独保存在 live-worker/observations/， 绝不把新像素绑定到旧 observation 身份。捕获失败也只记传感器诊断错误；捕获后 再核对 round、物理时钟、sim_steps、native_actions、proprioception，变化仍拒绝。

M7.4b 修复：冻结工具定义与诊断 runtime 的差异

Phase-one completed-snapshot replay (P1-S4)

These options select a separate implementation from the legacy M7 diagnostic path. Existing plain --at, including --live --execute-action, retains its previous behavior. The snapshot path never executes tool actions or answers a planner query from historical results.

# Before a parent call: completed snapshot plus tool-state deltas.
ora toolkit replay RUN --snapshot --at 3 --script trial.py --args '{}' --json

# A completed publication, with no implied parent tool arguments.
ora toolkit replay RUN --step 2 --script trial.py --args '{}' --json
ora toolkit replay RUN --step 2 --tool compute --args '{"expressions":"x = 6 * 7","outputs":["x"]}' --json
ora toolkit replay RUN --step 2 --tool check_task --args '{}' --json

# Explicit fresh perception, using original snapshot pixels.
ora toolkit replay RUN --snapshot --at 0 --script ora/agent/toolkit/examples/ground_geometry.py \
  --args '{"camera":"head","text":"cup","max_candidates":1}' --service-report SERVICE_REPORT --json

--at, --step and --native-action are mutually exclusive. --step and --native-action imply --snapshot. Snapshot options reject legacy --live and --execute-action; only native-action restoration accepts/requires an already allocated --resource-profile. Use plain --at for legacy diagnostics.

--snapshot --at verifies the selected publication's full state chain and replays tool-state writes only up to that parent. It uses only that exact parent's frozen tool-input table, matched by model-call identity, tool-call identity and observation binding. --step has no parent table: state, privileged, perception, compute and pure lib scripts are usable; tools requiring unrecorded dynamic configuration or targets fail with explicit missing requests. Neither selector scans later input tables or final artifact stores to fill gaps.

--tool with another tool than the parent's, or with other arguments, gets the configuration the live dispatch would have built for that call (snapshot_config.py). The parent table's frozen part (host/runtime/inputs.freeze) is the same for every tool at one boundary and is kept; the per-call sections are rebuilt with the live builders over a read-only host that sees the run as it was at the boundary (its current observation and the policy-state chain cut at the parent's publication): geometry_query and vision_segment from their step argument, observe from the boundary state. A step published after the boundary is refused as the live runtime refused it then. The parent's own tool with its own arguments keeps the recorded configuration. Where the boundary has no evidence for the request (the parent was compute, observe, report_issue or finish_episode, whose calls freeze no tool configuration; a finish_episode lifecycle section outside a finish_episode boundary; no parent row) the result is NotRecorded with a refusal object {status: "refused", reason, tool, section, usable_boundaries: [{at, tool}]} naming the parents whose recorded configuration serves the requested tool.

mode: snapshot results carry the selected state hash/boundary, private final tool-state values, source request context, progress/timing, missing requests and service comparisons. capability_override identifies the RSI-only task-check access; it reads the recorded boundary verdict and never runs a live check. The additive CallContext boundary {kind: "snapshot_step", step: K} identifies a completed publication without claiming an original parent invocation. Output uses the same separate toolkit-replay directory convention as diagnostics. Scripts run in-process and are trusted local code; this is not process isolation.

Native-tick snapshot restoration

# The resource profile is supplied by the caller; this command does not schedule it.
ora toolkit replay RUN --native-action 6 --resource-profile ALLOCATED_PROFILE \
  --script ora/agent/toolkit/examples/ground_geometry.py \
  --args '{"camera":"head","text":"cup","max_candidates":1}' \
  --service-report SERVICE_REPORT --json

N is the number of completed native actions (ticks): select the end of the controller sample whose native_action equals N. With a controller counter starting at 1, --native-action N means after the Nth tick. N=0 means reset, before any native action. An action interval [first,last] on the recorded 1-based tick labels corresponds to [first-1,last) on the completed-action axis. N is not a parent-tool ordinal or receipt index. If multiple rounds have the same N, report NotRecorded; this version has no implicit round choice.

native_boundary.py validates and truncates the controller trace and its ten physics lines per tick, preserving original and derived hashes separately in native-boundary.json. It maps action_id through the trusted execution ledger to its pre-action complete snapshot and unique execute_action begin. Tool deltas are applied through that interface ordinal, including multiple writes in that gap, without consuming the I/O cursor. Missing mappings or relevant gaps refuse reconstruction. No later input table or artifact directory supplies configuration. Native selection consequently has the same conservative script/configuration scope as --step; --tool requires explicit --args.

The independent diagnostic worker replays only this prefix, including preceding recorded render synchronizations. Every available control/physics prefix and endpoint measurement must match exactly before capture is granted. Captured object poses are also checked when present. Version/source fingerprint changes are warnings with both identities; evidence corruption and physical divergence still refuse. Unlike the legacy live path, fresh rendered pixels are the tool observation. Rendering must not advance physics. The source's old pixels are not relabeled as a new capture. This path makes no sensor byte-equality claim.

The worker, lease and scratch are released before the supplied script runs. The script receives the same detached snapshot facade: actions remain forbidden, planner reports SimulatorRequired, lifecycle/context requests only write output, and perception requests use the newly rendered images. Official status is read once from the verified restored simulator and exposed only through the RSI privileged/task-check capability. It does not use the source run's final verdict.

native-state.json records the fresh env values, reconstructed exec state and private tool overlay, bound to the original complete snapshot hash and action mapping. It is explicitly not an original completed-action publication and does not append to either source hash chain. The last receipt remains the last completed one; no current action's future receipt or final command buffer is imported. Current recovery previous anchors include the current pose action's pre-action update. Recovery/gripper/wait preserve their original anchors, as those execution routes do not call _remember_backtrack. Result replay_semantics=native_tick_fresh_render distinguishes this path from completed_snapshot; verification.json, stage progress/timings, warning evidence and independent service comparisons stay in the output.

Snapshot review boundaries

Snapshot service comparisons can refer to the selected parent's historical response, which occurred after its before-call boundary. They are therefore output-only audit evidence in comparisons.jsonl and its referenced CAS blobs. The script receives the new service response with Response.comparison=None. Neither historical response/array refs nor comparison blobs are granted to api.artifacts.read_blob. The legacy diagnostic comparison behavior is unchanged.

For --step, a complete physical/observation publication can occur inside an unfinished parent tool. A later zero-spend rollback or verify write can change tool.* before the policy resumes. When the snapshot watermark is inside such an invocation (or lacks complete tool-state evidence), the snapshot API omits all tool.* keys and reads report NotRecorded. result.json.missing_state_fields lists tool.* and its reason; exact published env.*, exec.* and privilege values remain available. To read settled policy-facing tool state, select the next parent with --snapshot --at K+1. Native reconstruction uses the raw publication plus verified deltas through execute_action begin instead; it does not infer a settled tool state from a step publication.

Before-parent selection rejects an action proposal, receipt or round reset between the last publication and the selected proposal. It does not combine a stale publication with a newer physical world. Intermediate native snapshots keep the pre-action exec.world_mutation_sequence: this counter advances when the real action receipt is committed, not merely when a tick finishes.

Native --tool currently admits only compute and check_task without a parent's frozen dynamic configuration. Other tools, unknown tools and invalid explicit arguments are refused before starting a worker; scripts may still use state, fresh perception and pure lib computations. The output may be any legal independent directory, including outside the global ORA workspace. Only the new native path places the worker at OUTPUT/environment, making the RPC shared root OUTPUT; the observation destination is checked against that root before staging resources. Source and output must remain disjoint. SIGTERM uses normal context unwinding to close the worker, release its lease and reclaim scratch; the signal handler is restored afterwards. The old live path retains its original output layout, diagnostic-source list and early-error behavior.

The native action/ledger link compares the submitted interface action after one validate_runtime_action pass against the stored owner action, exactly as the execution owner does before log.begin. This includes quaternion normalization. The ledger is not normalized a second time and no pose tolerance is introduced: different positions, orientations, observation bindings or extra fields still fail the action-identity check. Interface evidence remains in its original submitted form.

Protocol declaration (M7.6)

All new runs declare the manually numbered data-interface protocol in public toolkit-protocol.json, even when recording is off. Recording also declares it in native/toolkit-io/manifest.json and every begin/end event. Replay compares these declarations and reports both sides in protocol_compatibility; drift or missing legacy declarations warn and continue. Evidence integrity and physical restoration checks are unchanged. See protocol and gate audit for schemas, affected paths, decoder limits and version increment rules.
