ORA local CPU compatibility record

Status: source facts reviewed before authoring the local bundle; local rendering, reset and device qualification remain separate. This record follows the environment compatibility guide. It authorizes no simulator or provider launch and makes no Mac behavioral claim.

Sources and scope

The maintained source contract is LIBERO-Pro code 2b910b5b5f53016bef9907632f6f840f1ce2229c and data c86fc3b8293185a6f373677018ff3e37f8391602, owned by ora/environment/benchmarks/libero_pro.py. Task identity and public language come from that module and libero_pro_language.py; the isolated worker checks the actual loaded task against those inputs. RoboSuite 1.4.1 Panda, PandaGripper and OSC_POSE are the existing source-paired body/controller.

This treatment selects the existing direct driver, atomic v3 actions and bounded OSC executor. It removes the full baseline's CuRobo and resident perception dependencies; it does not alter their archived or maintained configurations. agent/composition/ora_local.py owns the local composition, while the ordinary server baseline remains unchanged. Local runs retain the ora-interactive namespace and normal Supervisor admission, leases, evidence and sealing.

Composition and delivery mapping

Planner/core reuse current canonical cross-task sources. Environment lifecycle reuses the current LIBERO boundary. The new local embodiment card states only the audited OSC/Panda facts above and binds a source-reference control profile; it does not activate a CuRobo motion profile or a physical grasp compiler. The isolated worker substitutes the version-matched opencv-python-headless distribution for RoboSuite's desktop opencv-python dependency. Both expose cv2; the selected offscreen environment never calls OpenCV's desktop renderer or the private segmentation-display path. This avoids a desktop libGL dependency without changing image/depth/calibration handling. The task slot receives the exact official source instruction once. All nine atomic tool schemas/effects reuse native_atomic_causal_v3; a new local_atomic_cpu_v1 manifest adds current required help without changing the old manifest. No segmentation, grounding, VLA or grasp-model endpoint is bound.

The local composition explicitly selects action v3, the local bundle/profile, disabled Task Memory and causal ActionStep context. Provider choice and endpoint are caller inputs; credentials are environment references, never prompt text. Runtime observations/receipts remain dynamic and authoritative.

Acceptance and limits

Before authoring, task/evaluator, body/control point, units, conversion direction, camera names and authority owners above were checked against current sources. No required source fact was filled from another robot or an old success video. The authored bundle must pass the simulator-free bundle audit and a freshly resolved RunPlan must select the local surface/context/profile, no GPU services and the exact source revisions. Focused tests cover input rejection, source and task identity, provider/resource propagation, first-message delivery and preserved server defaults. Existing atomic and OSC unit evidence is reusable because their implementation and schemas are unchanged.

Fresh local interpreter, source/assets, rendering, measured motion, reset and cleanup remain necessary device evidence. Until obtained, source composition and offline tests establish compatibility intent, not successful Mac operation. No benchmark success or cross-platform qualification is claimed by this record.
