Get started

Install ORA

One-line install

On Linux or macOS, with Git and curl:

curl -fsSL https://raw.githubusercontent.com/hao-ai-lab/ORA/main/scripts/install.sh | sh

scripts/install.sh needs no sudo. It installs uv into ~/.local/bin and Node.js 22.20 into ~/.local/share/ora/node when they are missing (the Node.js download is checked against its published SHA-256), checks ORA out into ~/.local/share/ora/ORA, runs the two install commands of the next section there, writes an ora command into ~/.local/bin and ends with ora doctor. ORA stays a Git checkout, so every run still binds the exact commit it ran. Rerun the command to update; it refuses a checkout with local changes. Options: sh -s -- --ref TAG installs a release tag, branch or commit, --dir, --bin-dir and --repo change where it installs and from where, and --no-doctor skips the check. Then install a simulator with ora setup --env <env> (one GPU). The rest of this page is the same installation by hand.

By hand

ORA's host environment needs Git, uv, Python 3.11 and Node.js 22.19 or newer with npm. uv can install the pinned Python version. Start with a source checkout so launches can record an exact Git commit.

git clone https://github.com/hao-ai-lab/ORA.git
cd ORA
uv sync --all-extras --locked
npm ci --prefix ora-pi --prefer-offline --no-audit --no-fund
uv run --locked ora doctor

--all-extras also installs the media extra (imageio, used by RoboTwin qualification captures) and the test runner; the same command is used everywhere in these docs.

ora doctor reports Python and ORA versions, the agent core's Node version and ora-pi packages, credential presence, and optional graphics/media dependencies. It does not print keys, authenticate a provider, or start a simulator. Missing simulator dependencies are expected at this step.

Node.js and the agent core

Model API policies run on the Pi agent core by default: TypeScript in ora-pi/ on the exactly pinned Pi packages, which Node.js 22.19 or newer runs directly, with no build step. Without sudo, unpack Node into ~/.local (macOS: darwin-arm64):

mkdir -p ~/.local && curl -fsSL https://nodejs.org/dist/v22.20.0/node-v22.20.0-linux-x64.tar.xz \
  | tar -xJ -C ~/.local --strip-components=1
export PATH=~/.local/bin:$PATH
npm ci --prefix ora-pi --prefer-offline --no-audit --no-fund

ORA uses ORA_NODE when it is set, else the first Node.js 22.19 or newer among node on PATH, ~/.local/bin/node and nvm installs (newest first), so a distribution Node 18 earlier on PATH does not block it. ora setup (both the CPU and --env forms) runs the same npm ci and leaves ora-pi/node_modules/ alone when every package already matches ora-pi/package-lock.json. On a host without registry access, npm ci --prefer-offline succeeds only from a populated npm cache: run it once where the registry is reachable with the same cache, or point npm_config_cache at one.

Preflight refuses a plan whose Node or packages are missing, naming the fix. Every native_api policy runs on the Pi core, so a model run needs them; see agent core.

Synthetic uses a real model API. Cost and latency depend on the endpoint; a self-hosted service can use the same interface.

Terminal UI (optional)

ora watch, ora interactive and ora local draw with a small Node front end (pi-tui) that ships with the agent core in ora-pi/src/watch/. The agent core's npm ci --prefix ora-pi above installs everything it needs; there is no separate step.

Without those packages, ora watch uses a built-in text view; the interactive commands need the front end (ora setup installs it for ora local).

ora interactive without --spec, ora play, ora attach and ora sessions use the Pi agent core's own terminal UI instead, and need only the agent core above; see interactive sessions.

ORA's web page for a live run (ora web) is built once with ./scripts/ora web setup (npm ci and a build in ora-pi/web/); see web view.

Next step

Run the first episode, then run robot tasks on one GPU or choose a robot environment. To give a robot instructions yourself, try free play (ora play --env synthetic needs no simulator); to drive a GPU server from your own computer, see remote use.

Developer installation

uv sync --all-extras --locked
npm ci --prefix ora-pi --prefer-offline --no-audit --no-fund
uv run --locked python -m pytest tests

The full suite needs system FFmpeg for video tests. See contributing. Preview these docs with ./scripts/docs serve (Node.js 22.19 or later); documentation dependencies are isolated from the runtime.
