Core Problem

幸存者偏差

WWII: 军方加固弹孔多的部位 → 错误。应该加固弹孔少的部位 — 那些飞机没回来。

我们的版本

  • 只看成功 trajectory 归纳 → 提取的 pattern 只是"幸存者的共性"
  • gen6 GRPO 失败了 → pipeline 学到"别用 GRPO" → 错误结论
  • 真正该问的: 失败是因为 lr 太高? 数据太少? 还是方法本身不行?

被动观察 = 只看飞回来的飞机
主动验证 = 控制变量，搞清楚哪些飞机为什么没回来

Framing

y = kx + b

y = kx + b y = 打榜分数 x = 迭代轮次 k = 迭代策略 b = inductive bias

AutoResearch

离散高 b 点。每个 = 一套完整 codebase。换 task 需要全新的 b，无迁移。

Ours (now)

连续 curve，每版 harness 是一个点。但 k→0 后停滞。

Ideal (goal)

同样低 b + 持续正 k。跨 task 复合增长。

我们交付 k（迭代策略）
不是交付 b（具体 recipe）

09

What We Deliver

理想的 k 是什么

1

主动高效探索环境，利用轨迹

不是被动等 trajectory 积累 → 主动设计实验验证假设。每轮 trajectory 有明确目的，信号密度 10x。

2

Across tasks 泛化

在 GSM8K 上学到的迭代策略，能迁移到 HumanEval / BFCL / GPQA。不是每个 task 从零开始。

3

Coarse-to-fine: 先探索环境，后验证策略

短 job (30min-2h) 快速排除错误假设 → 确认有效后才投入 10h 全量。不把 8h 赌在第一次决策上。

4

避免幸存者偏差

不只看成功 trajectory 归纳 — 主动验证失败假设为什么失败（gen6 GRPO 失败 = lr 太高? 还是方法本身不行?）

最终交付: 带着这个 k 的 harness → agent 在 PostTrainBench 10h setting 上跑 → 分数 = k 的质量指标。

11

Root Cause

被动观察 vs 主动科学

现在: 流行病学家

Agent 跑 10h → 产出 trajectory → Framework 被动看 → 提取 pattern → 生成 skill 问题: agent 从没试过 RL → 永远观察不到 "RL 比 SFT 好"

想要: 实验科学家

Framework 提出假设 → 设计验证实验 → 短 job 验证 (1-2h) → confirm/reject → 编码为 skill 优势: 每个 skill 有因果证据 不依赖 agent "碰巧"做了什么
12

Solution

Hypothesis-Driven Loop

┌──────────────────────────────────────────────────┐ │ │ │ ① HYPOTHESIZE │ │ current skills + blind spots + external knowledge │ │ → ranked hypotheses │ │ │ │ ② DESIGN │ │ → verification job matrix (30min-2h, A/B) │ │ │ │ ③ EXECUTE │ │ → 并行跑 verification jobs │ │ │ │ ④ INTERPRET │ │ → confirmed/rejected + skill draft │ │ │ │ ⑤ ACCUMULATE → 最终 harness │ │ │ │ ⑥ BENCHMARK (周期性) → 10h 全量打榜 │ │ │ └──────────────────────────────────────────────────┘
13

Architecture

双路径并行

┌→ 被动观察路径 (Stage 1-4) 10h 打榜 traj ───┤ → defensive skills (format, EOS, temp) │ └→ Blind Spots ──┐ ├→ Hypothesis Generator External Knowledge ────────────────┘ │ ▼ Verification Jobs (30min-2h, A/B) │ ▼ Interpreter → offensive skills │ ▼ 最终 Harness = defensive + offensive → 打榜

路径 A (被动) 产出防错 skill — 已穷尽但仍需要
路径 B (主动) 产出策略 skill — 新增，有因果证据

Iteration Speed

Day 1: 4 hypotheses → 8 jobs (1-2h) → confirm 2, reject 2 Day 2: 4 new hypotheses → 8 jobs → confirm 2, reject 2 Day 3: 4 confirmed → harness → 10h 打榜 验证假设数: 4-8/轮

Summary

一句话

Framework 的角色从
被动观察 trajectory → 归纳 pattern → 防错 skill
升级为
主动提假设 → 设计实验 → 验证 → 有因果证据的策略 skill

这不是替换现有 pipeline，是在现有 pipeline 旁边开辟第二条路径。
Defensive skills 保底，offensive skills 突破。
